# Edion — notes for coding agents

Electron video editor. Read `README.md` → Architecture first.

## Commands

- `pnpm typecheck`, `pnpm test` (core unit tests), `pnpm test:export` (builds, then headless end-to-end exports), `pnpm format`.
- Never launch the app visibly to check something. Use the offscreen hooks instead (invisible and muted):
  `EDION_OPEN=tests/fixtures/demo.edion EDION_SCREENSHOT=/path/out.png [EDION_DEBUG_SCRIPT=/path/script.js] pnpm exec electron .`
  after `pnpm exec electron-vite build`. The same variables work with `pnpm exec electron-vite dev`, which is the only way to catch dev-only bugs (React StrictMode mounts every effect twice, so anything created in an effect must be safely disposable and re-creatable). `tests/fixtures/` is generated by `pnpm test:export`.

- In `EDION_SCREENSHOT` runs the page exposes `window.__edion` (`core`, `editor`, `commands`, `session`, `projectActions`), so a debug script can drive the editor and return state as JSON instead of faking pointer events.
- `CI=1 EDION_E2E_NO_GPU=1 pnpm test:export` reproduces the GitHub runner locally (no sandbox, software WebGL).
- Automated runs (`EDION_SCREENSHOT`, `EDION_HEADLESS_EXPORT`) use a throwaway profile in the temp dir, so they never touch the user's real settings, recents or autosaves.
- In `pnpm dev`, editing a plain `.ts` file under `src/` triggers a full page reload instead of a hot swap (see `fullReloadForLogic` in `electron.vite.config.ts`): stores and the engine hold singletons, and hot-swapping them leaves two copies alive.

## Rules of the codebase

- `src/core` stays pure (no DOM, Electron or Node imports) and every behaviour change there gets a unit test.
- All project mutations go through `edit()` in `src/renderer/src/store/editor.ts` using ops from `src/core/ops`; wrap drags in `beginTransaction` / `commitTransaction` so they undo as one step.
- Preview and export must keep sharing `SceneRenderer` + `Compositor`. Anything visual is added to `evaluateScene` / the compositor, never to only one of the two paths.
- New effects: add the spec to `src/core/effects/registry.ts` and a fragment shader with matching uniform names to `engine/compositor/shaders.ts`. Transition order in the registry is the shader's `u_type`.
- IPC is typed in `src/shared/ipc.ts`; add the channel there, then main handler, then preload bridge.
- Prettier reformats on `pnpm format`; match its output when patching files.
